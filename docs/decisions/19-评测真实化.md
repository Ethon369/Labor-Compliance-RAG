# 19 · 评测真实化：占位 vs 真 bge-m3/bge-reranker

> V2.4 收尾决策记录。对应 `.env`（siliconflow 模式）、`scripts/backfill_embeddings.py`、
> `eval/runner.py`、`tests/test_rag_db.py`（模型一致性自检）。格式约定（CLAUDE.md 第 6 条）。

## 1. 一句话结论

**把 50 问评测从"离线占位"（HashEmbedder + TermOverlapReranker，词面重叠语义）
切到"真模型"（硅基流动 bge-m3 + bge-reranker-v2-m3）后，纯向量 Recall@8 从 0.6352
飙到 0.9686（HitRate@8 满分 1.0），混合+rerank 从 0.8145 升到 0.9654——证明此前
"混合 < 纯BM25"的结论是**占位向量拖累的假象**，真语义向量下两条检索路真正互补。**

## 2. 目标

- 让 README 上的评测数字反映"上线后真实会用到的模型"，而不是占位物。
- 量化"占位 vs 真模型"的差距——这个数字本身比任何占位结论都有说服力。
- 把"评测基线"从占位数字切换为真模型数字，并守住一条新架构约束：**库内向量必须
  与检索/评测 query 同一模型生成**。

## 3. 选中的方案

### 真实化操作链（三条命令，可复现）

| 步骤 | 命令 | 作用 |
|---|---|---|
| 1 | `.env` 设 `SILICONFLOW_API_KEY` + `EMBEDDING_MODE=siliconflow` + `RERANK_MODE=siliconflow` | 检索/评测走真模型 |
| 2 | `python scripts/backfill_embeddings.py --force --kb-id 1` | **默认库 205 片向量从占位重灌成真 bge-m3**——不重灌会让 hash 文档 × bge query 错配，检索无意义 |
| 3 | `python eval/runner.py --top-k 8` | 真 embedding + 真 rerank 跑 50 问 |

### 占位 vs 真模型数字

| 方法 | 占位 Recall@8 | 真模型 Recall@8 | 占位 HitRate@8 | 真模型 HitRate@8 |
|---|---|---|---|---|
| 纯向量 | 0.6352 | **0.9686** | 0.6792 | **1.0000** |
| 纯BM25 | 0.7893 | 0.7893（不变） | 0.8302 | 0.8302（不变） |
| 混合(RRF) | 0.7421 | **0.9277** | 0.7925 | **0.9623** |
| 混合+rerank | 0.8145 | **0.9654** | 0.8491 | **0.9811** |

（BM25 两列相同是预期：BM25 是词面匹配，不依赖 embedding，本来就在算真实分数。）

## 4. 三个洞察（可直接引用）

1. **占位向量 ≈ 词面匹配，藏住了语义检索的价值**。HashEmbedder 是"词元集合的稠密
   投影"，能力上等价于另一个 BM25——所以占位评测里"纯向量(0.64) ≈ 纯BM25(0.79)"
   甚至更差。真 bge-m3 把纯向量拉到 0.97，才让向量路真正显出"语义召回"（同义改写、
   语序无关都能命中）。
2. **旧结论"混合(RRF) < 纯BM25"是假象，且自己解释了原因**。占位向量路带入的
   词面噪声在 RRF 里挤占 BM25 的高质量位置，导致融合反而退化（决策 04 当时如实记录
   了这种现象，但没料到是占位件的系统性偏差）。真向量下 RRF=0.9277 高于 BM25 的
   0.7893——两条互补的路（语义 + 词面）融合后才是最优。
3. **rerank 的真位置：把"两路都召回的精确条文"排到最前**。真模型下 rerank 仍比
   RRF 高（0.9654 vs 0.9277），且 `test_fused_*` 曾验证命中切片两路 lane 都在——
   融合召回、精排排序的两段式设计经受住了真模型考验。

## 5. 测试与工程配套

- **测试永远离线**（conftest 强制 `EMBEDDING_MODE=offline`）：防止本机 .env 配了真
  key 后 pytest 意外调 API（慢、花钱、网络抖动）。
- **库向量模型一致性自检**（`test_rag_db.py`）：hash-embed 库内首片查自己，命中 = 库是
  占位向量，继续断言；未命中 = 库已被真模型重灌 → 离线断言失去意义 → skip（真模型库
  的验收交给 `eval/runner.py` 真实结果）。这让测试对"库当前是哪个模型"无偏。
- 占位环境的四数字基线（0.6352/0.7893/0.7421/0.8145）不再作为验收线；真模型数字
  成为新的默认评测基线。

## 6. 已知取舍

1. **真模型评测有成本且非离线可复现**：每次重灌 + 评测约消耗几毛到几块、需真 key。
   离线占位仍保留（无 key 时全链路可跑），只是数字口径要讲清是"占位"。
2. **重灌覆盖原向量不可逆**：`backfill --force` 后旧 hash 向量没了；换回 offline 模式
   需再 `--force` 重灌一次。
3. **个人简历库等其它库也要重灌**（本次已一并处理），否则库内 hash 与 bge 混用会
   检索劣化——"换模型 = 全库重灌"是 pgvector 方案的固有约束（无多租户向量分区）。
4. **评测 query 全走真 API，本地评测变慢**（约 3 分钟/轮 vs 占位秒级）。
